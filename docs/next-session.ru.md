# Промпт для следующей сессии

Работай в `bignstrong/opencode-rage`. Rage — один устанавливаемый TUI-плагин OpenCode. Диктовка, кнопки и орбы уже работают. Раздели их ответственность внутри пакета, чтобы следующую функцию можно было добавить, не меняя код записи. Пользователь по-прежнему подключает только `rage`.

1. На ветке `main` начни с `rust/MAP.md` и `rust/qa/README.md`. На macOS Rust включён по умолчанию. `native/src/` отвечает за запись, устройства, модели и запуск распознавания; `native/host/src/` за команды, настройки, состояния и кадры орба. `src/tui.ts` связывает их с OpenCode. Проследи одну запись от кнопки до черновика. Запусти `npm run build:native && npm run check`.
2. Предложи короткую карту: кто владеет записью и распознаванием, кто кнопками и действиями черновика, кто анимацией. Укажи конкретные файлы и зависимости. Если граница уже есть, не переделывай её ради новой папки.
3. Сразу внеси минимальный рефакторинг. Оставь единый вход V2 и действующий адаптер V1. Не создавай монорепозиторий, отдельные npm-пакеты или внутренний фреймворк плагинов. `/voice`, `/voice-submit`, `/voice-stop`, `/voice-settings` и `/orbs` должны работать как раньше.
4. Проверь поведение: кнопки не теряют черновик и вложения; обрыв связи с микрофоном не отправляет частичный текст; подключение нового входа обновляет открытый список; смена орба не запускает запись. Сохрани настройки, кеш моделей и совместимость команд. Для микрофонов используй тестовые устройства, не записывай реальный звук.
5. Запусти `npm run check` и `npm pack --dry-run --ignore-scripts`. При изменениях TUI проверь установленный tarball в реальном OpenCode с синтетическим входом. Для сравнения задержки используй `rust/qa/compare-inference.mjs` и `docs/performance.ru.md`. Перечисли доказанные совпадения и оставшиеся расхождения. Не публикуй npm-релиз.
