# Офлайн A/B: ASR для русского wake

Apple M2 Max, macOS 27.2.1. `whisper.cpp` v1.8.2 с `ggml-large-v3-turbo-q5_0.bin` против установленного `opencode-voice-transcribe` с `gigaam-v3-e2e-ctc-Q4_K_M.gguf`. Это сравнение двух рабочих связок движок/модель, а не моделей на одинаковом рантайме.

```sh
python3 -B rust/qa/wake-asr.py \
  --listen native/target/release/rage-core \
  > "${TMPDIR:-/tmp}/wake-asr-results.jsonl"
```

`--listen` использует готовый `rage-core`. По умолчанию скрипт ищет движки в `~/.cache/opencode-voice/engines`, модели в `~/.cache/opencode-voice/models`. Если файлов там нет, укажите пути через `--whisper`, `--whisper-model`, `--gigaam`, `--gigaam-model`. Локальный голос Milena должен быть установлен. WAV удаляются после прогона. Синтез, декодеры и replay запускаются с запретом сети через `sandbox-exec`.

## Метод

- Milena, 155/185 слов в минуту, моно PCM16 16 кГц. Десять команд синтезированы отдельно без имени и целиком с «Рейдж». Внутренняя пауза 380 мс, пауза после имени 450 мс. Ещё три клипа по 3 секунды: цифровая тишина, гул с белым шумом, тот же фон со щелчками.
- Оба движка получают один и тот же WAV каждой пары, язык `ru`, без очистки FFmpeg. Порядок движков чередуется. Медиана прямого вызова включает запуск процесса, чтение модели и декодирование, не включает синтез.
- WER: сумма редакционных расстояний по словам, делённая на сумму слов эталона. Регистр, пунктуация и `ё/е` игнорируются; `Git` и `гит` различаются. В прямом прогоне для WER удаляются включения в квадратных и круглых скобках, как в wake. Для шума считаются отдельно любые непустые ответы и ответы после этой очистки.
- Дополнительный `listen --wav` использует встроенный детектор и реальную обрезку перед ASR. В эталоне нет wake-имени. Если команда не дошла до декодера, это провал replay, но не ошибка модели; смотрите `heard` и отдельные результаты клипов. В replay строка `text` берётся из события Rage после обработки, не из stdout декодера.

## Результат

| Набор | Whisper Turbo Q5_0 | GigaAM v3 Q4_K_M |
|---|---:|---:|
| Без имени, 10 команд | 7,0% WER (3/43), 7/10 точных | 9,3% (4/43), 6/10 точных |
| С именем, 10 команд | 5,7% (3/53), 7/10 точных | 15,1% (8/53), 4/10 точных |
| `listen --wav`, 6 команд | 12,0% (3/25), 3/6 точных | 16,0% (4/25), 2/6 точных |
| Прямой ASR, непустые ответы на тишину/шум | 3/3 до и после очистки | 0/3 до и после очистки |
| `listen --wav`, срабатывания / непустые ответы на тишину/шум | 0/3 и 0/3 | 0/3 и 0/3 |

Детектор услышал все 6 команд на обеих настройках. Медиана прямого вызова на речевых клипах: 792–803 мс у Whisper, 177–181 мс у GigaAM, в зависимости от набора. Это около 4,5 раза, не ускорение полного wake-turn. Оба декодера написали «5» вместо «пять» в обоих прямых наборах: если считать их эквивалентными, у каждого на одну ошибку меньше в каждом наборе, сравнительный вывод не меняется.

Примеры без правки пунктуации:

| Вход | Whisper | GigaAM |
|---|---|---|
| Прямой ASR без имени, «глянь какие есть нейроны» | «Глянь, какие есть нейроны.» | «Глянь, какие есть нейроны.» |
| Прямой ASR без имени, «глянь какие есть нейросети» | «Глянь, какие есть нейросети.» | «Глянь, какие есть нейросети.» |
| Wake replay, «Рейдж глянь какие есть нейроны» | «Пидж глянь какие есть нейроны.» | «Ижзглянь, какие есть нейроны.» |
| Wake replay, «Рейдж глянь какие есть нейросети» | «Идж глянь какие есть нейросети.» | «Ижзглянь, какие есть нейросети.» |
| Wake replay, «Рейдж открой настройки» | «Открой настройки.» | «Открой настройки.» |
| Wake replay, «Рейдж открой репо…» | «Открой репа и покажи последние изменения.» | «Открой репу и покажи последние изменения.» |
| Wake replay, пауза после «репозиторий» | «Проверь репозиторий и покажи, что изменилось.» | «Проверь репозитори и покажи, что изменилось.» |
| Wake replay, пауза после имени | «Открой последние логи.» | «Открой последние логи.» |
| Прямой ASR, каждый из трёх фоновых клипов | «Продолжение следует...» | пусто |

**Решение:** не менять модель ради исправления wake на основании этого прогона. Оба движка различают «нейроны» и «нейросети»; на слитном «Рейдж глянь» оба портят начало. Полный клип и команда без имени читаются правильно, поэтому сначала стоит проверить WAV на входе ASR после обрезки wake. Если цель отдельного эксперимента — скорость, GigaAM имеет смысл пробовать только в изолированном launcher, не меняя модель ручной диктовки или глобальные настройки.

## Эксперимент с началом команды

```sh
python3 -B rust/qa/wake-asr.py --onset \
  --listen native/target/release/rage-core \
  --gigaam /path/to/opencode-voice-transcribe \
  --gigaam-model /path/to/gigaam-v3-e2e-ctc-Q4_K_M.gguf \
  > "${TMPDIR:-/tmp}/wake-asr-onset.jsonl"
```

`--onset` компилирует только standalone-драйвер детектора локальным `rustc` во временную папку. В replay декодер-заглушка копирует входной WAV; PCM после нулевой подкладки сопоставляется с исходником побайтово. Standalone-драйвер даёт время конца кадра с hit. В чистом исходном PCM ищется единственная серия из ≥2 шумных кадров (10 мс, ≥45 пересечений нуля, RMS ≥180), пересекающая окно hit ±100 мс. Для `burst-end-fallback`, если таких серий нет, порог снижен до 25 пересечений. Конец серии — акустический ориентир хвоста `/ж/`, не независимая фонетическая разметка и не доказанный конец слова.

Для измерений использован уже собранный `rage-core` (SHA-256 начинается с `d62fc637653a13f1`). Перезапуск с другим бинарём проверяет поведение этого бинаря, а не автоматически текущего Rust-исходника.

Декодеры получают одинаковые варианты: фактический crop, цельная фраза до того же конечного кадра, crop в hit, crop в hit +60 мс, crop после найденной серии. Все отсечённые варианты получают одинаковые 200 мс нулей слева. Для полного WAV проверяются точное имя и первое слово после него; для отсечённых вариантов проверяется первое слово в начале ответа. Стоп-слова и исправление распознанного имени не применяются. Исходный набор: четыре команды («глянь» ×2, «открой» ×2), 135/155/190 слов в минуту. Проверочный: «сохрани», «прочитай», «что», «жми» при 145/180, в том числе первые согласные, которые легко спутать с шумным хвостом имени. Дополнительная проверка: однословные «стоп», «да», «вверх» при 145/180.

Два `fallback-only` показателя выбирают альтернативный WAV, только если фактический crop оставил все 100 мс до hit. `fallback-only-burst` также оставляет исходный crop, если нет единственной серии. Это расчёт по уже полученным ASR-ответам, без изменения Rage.

### Где начинается вход ASR

Время от начала исходного WAV при 155 словах в минуту:

| Команда | Первый исходный кадр в ASR (после 200 мс нулей) | Hit | Конец шумной серии |
|---|---:|---:|---:|
| «Рейдж глянь какие есть нейроны» | 410 мс | 510 мс | 570 мс, только сниженный порог |
| «Рейдж глянь какие есть нейросети» | 420 мс | 520 мс | 570 мс, только сниженный порог |
| «Рейдж открой настройки» | 690 мс | 600 мс | 700 мс, исходный порог |
| «Рейдж открой репо…» | 650 мс | 570 мс | 660 мс, исходный порог |

На обеих фразах с «глянь» исходный порог не нашёл серии ни в одном из трёх темпов. В ASR вошли 100 мс до hit. При 155 словах в минуту hit произошёл за 50–60 мс до конца серии на снижённом пороге; фактический crop опережал эту отметку на 150–160 мс. Смена начала на hit +60 мс оставила для обоих движков «Глянь, какие есть нейроны.» / «Глянь, какие есть нейросети.». Срез ровно в hit ещё давал «Жглянь» (Whisper) и «Вглянь» (GigaAM). На «Рейдж открой репо…» при 135 словах в минуту GigaAM с hit +60 мс выдал «Шткрой реп и покажи последние изменения.».

### Первое слово команды

В ячейках Whisper / GigaAM. Для полного WAV засчитано первое слово **после** имени, даже если само имя искажено.

| Вариант | Исходные 12 | Проверочные 8 | Однословные 6 |
|---|---:|---:|---:|
| Фактический crop | 6/12 / 6/12 | 8/8 / 8/8 | 4/6 / 2/6 |
| Полный WAV | 12/12 / 12/12 | 8/8 / 8/8 | 5/6 / 4/6 |
| Срез в hit | 4/12 / 2/12 | не запускался | не запускался |
| Срез в hit +60 мс | 12/12 / 11/12 | 8/8 / 8/8 | 6/6 / 4/6 |
| Срез после серии, включая сниженный порог | 12/12 / 12/12 | 6/6 / 6/6, у двух клипов нет однозначной серии | 6/6 / 4/6 |
| Любой из двух `fallback-only` | 12/12 / 12/12 | 8/8 / 8/8 | 6/6 / 4/6 |

Цельный WAV вернул точное имя на всех 12 исходных клипах, но только на 5/8 проверочных у Whisper и 2/8 у GigaAM. Пример: «Рейд, что изменилось в репозитории.» (Whisper), «Rейt, что изменилось в репозитории?» (GigaAM). Считать всю фразу чистой командой нельзя: в тесте она начинается с имени, а в жизни перед ним может быть речь.

На «Рейдж да» hit, напротив, на 10 мс **позже** конца серии в обоих темпах. Срез после серии оставляет на 70 мс больше исходного звука, чем hit +60 мс. Оба варианта дали «Да.» вместо «Жда.». На «Рейдж стоп» у GigaAM остаются ошибки и без новой обрезки (`top.`), и со срезом после серии («Ттоп.»). Это отдельный случай.

**Кандидат для интеграции:** не менять успешно найденную границу. Если иначе сохранился бы весь pre-roll, пробовать срез после единственной близкой серии на снижённом пороге; при отсутствии однозначной серии не менять crop. В этой синтетической выборке первое слово исправилось на восьми клипах для каждого движка без новых ошибок. Фиксированные +60 мс дали тот же счёт только при ограничении на fallback, но не привязаны к акустической границе. Универсальную правку этот тест не доказывает: низкий порог может принять начальную согласную команды за хвост имени. Перед интеграцией нужны независимая разметка границы и случаи с речью до обращения. `native/src/listen.rs` не менялся.

Точный регрессионный критерий для двух реплик с «глянь»: после повторного прогона `--onset` следующие 12 ответов (два движка × две реплики × три темпа) должны быть точными. На исходном `rage-core` этот критерий ожидаемо не проходит.

```sh
jq -s -e '
  [.[] | select(.kind == "onset-clip" and .variant == "native"
    and (.label == "neurons" or .label == "networks"))] |
  length == 12 and all(.[]; .first_ok and .edits == 0)
' "${TMPDIR:-/tmp}/wake-asr-onset.jsonl"
```

## Границы

Один синтетический голос без перегруза, речи на фоне речи и комнатной акустики. Тест не включает микрофон, частные записи, сеть или пользовательский профиль wake. Прямой результат без имени не заменяет захват wake; краткий шумовой тест не оценивает частоту ложных срабатываний в быту. Абсолютные времена не переносимы на другие Mac.
